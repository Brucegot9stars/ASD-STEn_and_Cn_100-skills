# 两个 skill 的关系与中英文混合文本处理

本文件在 `asd-ste100-technical-writing/` 与 `ste-zh-technical-writing/` 两个仓库各存一份，内容一致。改动时两边同步。

## 1. 结论：不合并，分两个

两个 skill 是**互补但不可合并**的独立能力。合并成一份规则集会造成硬冲突：

| 维度 | `asd-ste100-technical-writing` | `ste-zh-technical-writing` | 合并后果 |
|---|---|---|---|
| 依据 | ASD-STE100 Issue 9，官方标准，仅英文 | 该方法的中文适配，非官方 | 合规声明边界被模糊 |
| 句长单位 | 程序句 ≤ 20 词，描述句 ≤ 25 词 | 操作句 ≤ 30 字，描述句 ≤ 40 字 | 同一句不知道用哪套 |
| 词汇控制 | 约 900 批准词加约 1200 不批准词 | 约 110 条中文词表 | 词典互相污染 |
| 语法限制 | 禁 `-ing`、完成时、缩写、名词簇 ≤ 3 词 | 禁名词化、长定语、`以上/以下`、被字句 | 中文没有词形变化，英文没有"进行+动词" |
| 安全提示 | `WARNING` / `CAUTION` / `NOTE` | `警告` / `注意` / `说明` | 级别需映射，不能混写成一套 |
| 可声称 | 按 ASD-STE100 Issue 9 写作规则改写 | 按受控中文规则改写 | 中文部分被误标为合规，风险最高 |
| 触发语义 | 英文手册、工卡、SOP | 中文手册、工卡、SOP | 一个 description 塞两套语义，召回变差 |

所以：**两个 skill，各自独立安装、独立触发、独立检查**。两者共享工程外壳，包括目录约定、安装器、顶层 CI 和许可。规则集不合并。

## 2. 中英文混合输出怎么处理

混合文本**不需要第三个 skill**。靠"按段落分诊加两个脚本各跑一次"解决。

### 2.1 标记每段的语言类型

| 类型 | 判定 | 交给谁 |
|---|---|---|
| `EN` | 英文主导，无汉字或汉字很少 | `asd-ste100-technical-writing` |
| `ZH` | 中文主导 | `ste-zh-technical-writing` |
| `MIXED` | 同一句内中英混排 | 按主导语言选一套，另一语言片段列为不可改字面量 |
| `CODE` | 代码、命令、路径、参数、错误串、UI 标签 | 原样保留，两个 skill 都不改 |

### 2.2 分诊规则

- **先分诊，再改写**。不要对整篇文档同时套两套规则。
- **一句只用一套句长上限**。中英混排句按主导语言判，不要既数词又数字。
- **不可改清单跨语言生效**。代码、命令、路径、数字、单位、版本和界面文字，两种语言里都逐字保留。
- **界面文字与术语**。中文正文里的英文界面文字用「」或反引号包裹，按字面量处理。英文正文里的中文译名同理，不改写，不强行翻译。
- **术语表建双语两份**。一词一义在各自语言内部成立，不跨语言强行统一词形。
- **同一概念在两种语言里各定一个名字**。在术语表登记对应关系，例如 `bearing` 对应 `轴承`。
- **安全提示双语时级别必须一致**。`WARNING` 对应 `警告`，管人身伤害。`CAUTION` 对应 `注意`，管设备损坏。`NOTE` 对应 `说明`，只给信息，不含指令。两种语言都放在受影响步骤之前。
- **双语对照文档逐段分诊**。中文段与英文段并列时，两句之间不互译，不合并，不为"读起来顺"调换顺序。
- **合规声明分开写**。英文部分可写"按 ASD-STE100 Issue 9 写作规则改写"。中文部分只能写"按受控中文规则改写"。**整份文档不得声称"符合 ASD-STE100"**，因为中文部分不在该标准范围内。

### 2.3 检查流程

两个脚本默认开启语言感知跳过。英文脚本跳过中文主导行，中文脚本跳过纯英文行。双语文档可以直接各跑一次，互不误报。

```bash
python asd-ste100-technical-writing/scripts/check_en.py --strict 双语手册.md
python ste-zh-technical-writing/scripts/check_zh.py --strict 双语手册.md
```

两个脚本的输出合并看。**任一脚本出现【必须】级发现，整份文档不交付**。

若要强制检查全部行，加 `--no-lang-skip`。

### 2.4 人工复核

脚本查不出以下几项，必须人工判断：

- 双语术语是否一一对应，有没有同一部件在两种语言里换了叫法。
- 双语安全提示的级别与后果是否一致。
- 中文译文是否改变了英文原文的技术含义。
- 双语步骤编号是否仍然对齐，警告是否仍绑定同一条步骤。

## 3. 给 agent 的一句话指令

```text
这是中英混合文档。先按段落分诊：英文段用 asd-ste100-technical-writing，
中文段用 ste-zh-technical-writing，代码与界面文字原样保留。
一句只用一套句长上限。最后分别跑 check_en.py 与 check_zh.py，
并核对双语术语表与安全提示级别。
```

## 4. 一句话总结

**能处理混合输出，但不是靠合并 skill，而是靠分诊。** 两个 skill 各管一种语言，共享不可改清单、术语表结构、安全提示映射与交付格式。
