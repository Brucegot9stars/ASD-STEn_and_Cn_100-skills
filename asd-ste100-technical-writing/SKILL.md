# ASD-STE100 Simplified Technical English — 技术写作 Skill

## 1. 用途

把英文技术文档写成或改成**按 ASD-STE100（Issue 9）写作规则改写的受控英语**，让读者**一次读对、只有一种理解**。

STE 由两部分组成：

- **53 条写作规则**，分 9 节，管词、名词簇、动词、句子、程序、描述、安全说明、标点、写作实践。
- **受控词典**：约 900 个批准词（一词一义一词性）+ 约 1200 个不批准词及替换建议。

目标不是把英语写"简单"，而是把**歧义和人为差错风险**降下来。适用于程序、描述、安全说明及其混合文本。

## 2. 触发条件

### 2.1 应触发

- 用户提到：ASD-STE100、STE、Simplified Technical English、简化技术英语、受控英语、controlled English、controlled language。
- 用户要写或改：维修手册、工卡、安装/拆卸步骤、调试步骤、SOP、运行手册（runbook）、API 运维文档、安全警告。
- 用户要求：非母语读者一次读懂、消除歧义、便于翻译/机器翻译、可机械检查、统一术语。
- 行业场景：航空、国防、汽车、铁路、医疗器械、制药、能源、机械、IT 运维等受监管或安全相关文档。
- 用户要求"用 STE 的风格解释/写说明"（含给 LLM 的输出约束）。

### 2.2 不应触发

- 营销文案、品牌文案、销售页、发布公告：STE 会刻意删除说服力。
- 法律合同、法规原文、认证文本：不得改写，只能保留原文并另行说明。
- 文学、博客、对话式文档、需要作者个人风格的内容。
- 纯中文写作：STE 只规范英文；可借用其原则，但**不得声称符合 ASD-STE100**。中文文档改用 `ste-zh-technical-writing`。
- 代码、命令、日志、标识符、错误串本身：保留原样，只改其周围的散文。

### 2.3 中英混合文本

不合并两个 skill，也不做全篇双语改写。先按段落分诊，再分别处理：

- `EN` 段用本 skill，`ZH` 段用 `ste-zh-technical-writing`，`MIXED` 段按主导语言选一套，`CODE` 原样保留。
- 同一句内中英混排时，按主导语言选**一套**句长上限，另一语言片段列为不可改字面量。
- 建双语术语表，同一概念在两种语言里各定一个名字。安全提示级别必须对应：`WARNING` ↔ `警告`、`CAUTION` ↔ `注意`、`NOTE` ↔ `说明`。
- 检查时两个脚本各跑一次（默认各自跳过对方语言主导的行）。任一脚本有【必须】级发现，整份文档不交付。
- 合规声明分开写。英文部分可写"按 ASD-STE100 Issue 9 写作规则改写"，中文部分只能写"按受控中文规则改写"。整份文档不得声称"符合 ASD-STE100"。
- 完整规范见 `docs/mixed-language.md`。

## 3. 适用任务

| 任务 | 典型输入 | 交付 |
|---|---|---|
| 新写程序性文本 | 步骤要点、工程说明 | 编号步骤 + 前置条件 + 安全说明 |
| 改写既有文档 | 旧手册段落、翻译腔文本 | STE 改写稿 + 变更说明 |
| 写安全说明 | 风险描述、后果 | WARNING / CAUTION / NOTE |
| 统一术语 | 多版本手册、术语表 | 首选术语表 + 替换清单 |
| 合规自检 | 待审文本 | 逐条检查结果 + 问题清单 |
| 翻译前简化 | 源语言技术文本 | 低歧义英文源文 |
| 约束 LLM 输出 | "用 STE 写" | 受控英文 + 自检说明 |

## 4. 规则要点

> 以下是执行时必须遵守的硬约束。完整规则结构与示例见 `references/writing-rules.md`；词汇与语法细节见 `references/vocabulary-and-grammar.md`。

### 4.1 词汇

- **只用批准词**，且必须按词典给的**词性**和**批准含义**使用。
- **一词一义一词性**：同一概念全文用同一个词，禁止为"文采"换同义词。
  - `start`，不用 `begin / commence / initiate`。
  - `make sure`，不用 `ensure`（常见做法，最终以词典为准）。
  - `before`，不用 `prior to`；`use`，不用 `utilize / leverage`。
- **技术名词、技术动词可以使用**，但必须：来自项目术语表、图纸、官方文件或术语库；技术名词只作名词、技术动词只作动词（不互转）；全文写法一致；不得当成规避词典的"后门"。
- 用**美式拼写**。
- 不用缩写形式：写 `do not`、`cannot`、`it is`，不写 `don't`、`can't`、`it's`。
- 不用拉丁缩写：`e.g.`、`i.e.`、`etc.` 改为 `for example`、`that is`、`and so on`，或直接列举。
- 不用 `-ing` 动词形式；仅允许作技术名词或其修饰语（如 `opening`、`landing gear`、`setting`）。
- 不用性别代词 `he / she`；改用 `the operator`、`the technician` 或复数。
- 不用隐喻、习语、俚语、短语动词（用 `connect`，不用 `hook up`）。

### 4.2 名词簇

- 名词簇**最多 3 个词**。
- 超长时用介词、所有格、冠词拆开，露出各部分关系。
  - ✗ `forward turbine overheat thermocouple terminal tags`
  - ✓ `the terminal tags on the forward overheat thermocouple of the turbine`
- 不省略冠词 `a / an / the` 和连接词 `that`；不要为缩短句子删必要成分。

### 4.3 动词与语态

- 只允许这些动词形式：**不定式、祈使式、一般现在时、一般过去时、一般将来时（will）**；过去分词**只能作形容词**（`the changed file`）。
- 禁止：完成时（`has / have / had + 过去分词`）、进行时（`is / are + -ing`）、复杂助动词堆叠。
  - ✗ `The temperature must be adjusted.` → ✓ `Adjust the temperature.`
- **程序**：用主动语态 + 祈使句，明确施动者。
- **描述**：优先主动；只有施动者未知或不重要时才可用被动。
- 情态动词按词典批准义使用。常见做法：`can` 表能力/可能，`must` 表要求；不要用 `may / might / could / should` 表达模糊不确定性。

### 4.4 句子与段落

- **程序句 ≤ 20 词；描述句 ≤ 25 词。**
- **一句一个指令**；只有两个以上动作必须同时发生时才可同句。
- 一句一个意思；条件放在指令之前（`If ... , ...` / `When ... , ...`）。
- 复杂并列、三个以上同类项、连续步骤：用**竖排列表**，不要堆成一句。
- 一段一个主题，**最多 6 句**；主题句先行。
- 用 `then / because / but / so` 等明确连接词交代句子关系，不靠读者猜。

### 4.5 程序性写作

- 每条指令以**祈使动词**开头：`Remove the bolts.`，不写 `The bolts should be removed.`
- 按实际执行顺序编号；一步一个主要动作。
- 条件、位置、风险写在动作之前，或单独列为前置条件。
- 不把关键限制塞进步骤末尾的括号里。

### 4.6 描述性写作

- 短句 ≤ 25 词；按因果或时间顺序写。
- 先给最重要的信息；再给条件、原因、例外。
- 删除无信息量的软化语（如"可能""大概"），但**不改变原文的确定性**；把模糊感受改成**可检查的事实或条件**。
- 不用修辞、比喻、拟人。

### 4.7 安全说明

- `WARNING`：人身伤害或死亡风险。
- `CAUTION`：设备、工具或财产损坏风险。
- `NOTE`：仅提供信息，**不得包含指令**。
- 安全说明放在**受影响步骤之前**，不能放在之后。
- 先写**明确的命令或条件**，再写原因和后果。

```text
WARNING: DO NOT TOUCH THE EXHAUST DUCT. THE SURFACE IS HOT AND CAN CAUSE BURNS.
CAUTION: DO NOT USE WATER ON THE ELECTRICAL PANEL. WATER CAN DAMAGE THE CONNECTORS.
NOTE: The test takes about 5 minutes.
```

### 4.8 标点与字数

- 用标准英文标点，但**不用分号（;）**；拆成两句或改成列表。
- 不用 em dash / en dash 连接两个独立意思；拆句。
- 连字符只用于复合词和标识符。
- 列表用冒号引导；步骤按顺序编号。
- 统计句长时，标题、标牌、引用文本按**一个词**计；**数字 + 单位算一个词**（如 `10 °C`、`10 in.`）；代码、命令、路径按字面量处理，不参与改写。

### 4.9 一致性

- 同一部件、同一动作、同一状态，全文用**同一个名称**。
- 首次出现的缩写给全称，后文保持同一写法。
- 不为了"读起来不重复"而换词；**重复是正确，不是缺陷**。

## 5. 执行流程

1. **判定任务模式与文本类型**
   - 模式：改写 / 仅检查 / 仅保留原文。用户未指定时默认改写。
   - 仅检查：跳到第 5 步机械自检，只报发现，不改文本。
   - 仅保留原文：法规、合同、认证原文不改，另出说明。
   - 判定：程序 / 描述 / 安全说明 / 混合。
   - 确认读者、监管要求、目标 Issue（默认 Issue 9）。
   - 安全关键判据：航空、医疗、高压、带电作业场景视为安全关键。句长取程序 ≤ 20 词、描述 ≤ 25 词，安全说明逐条人工复核。
   - 完成标准：模式与句长档位已定，能说出每段属于哪一类。

2. **锁定不可改内容**
   - 代码、命令、路径、标识符、错误串、数字、单位、日期、版本、UI 标签、法规原文，逐字保留。
   - 完成标准：列出"不可改清单"，改写时不触碰。

3. **建立术语表**
   - 提取技术名词/技术动词，确定唯一写法、词性和含义。
   - 缺失时向用户询问，或标注"待术语委员会确认"。
   - 完成标准：关键对象、动作、状态各只有一个首选词。

4. **分层改写**
   - 顺序：词 → 名词簇 → 动词/语态 → 句子 → 段落 → 安全说明 → 标点。
   - 每改一层只解决该层问题，避免一次性重写导致技术信息漂移。
   - 完成标准：每句都能指出触发了哪条规则。

5. **机械自检**
   - 检查句长、`-ing`、完成时、进行时、缩写、分号、拉丁缩写、名词簇、段落句数。
   - 完成标准：`references/checklist.md` 的机械项全部通过。

6. **语义复核**
   - 技术含义是否改变？条件、限制、例外、警告是否还在？施动者是否明确？
   - 完成标准：请主题专家或用户确认无技术漂移。

7. **交付**
   - 输出改写文本 + 变更说明 + 待确认清单。
   - 完成标准：见第 6 节输出约束与第 7 节交付判定。

## 6. 输出约束

- **只改英文散文**。代码块、命令、路径、标识符、错误串、数字、单位、版本、日期、UI 标签原样保留。
- **不新增事实**：不添加来源没有的数字、条件、能力、结论。
- **不删信息**：警告、限制、例外、单位、默认值、失败处理必须保留。
- **不改变确定性**：原文的"可能/建议/通常"不得擅自升级为"必须/将会"。
- **不改写法律、法规、认证原文**；如与 STE 冲突，保留原文并标注。
- **不虚构词典批准状态**。无法确认时用简单常用词，并标注"需查 Issue 9 词典"。
- **不声称官方认证或"完全合规"**。最多写"按 ASD-STE100 Issue 9 规则改写"或"STE-style"。
- 默认交付三件套：
  1. 改写后的英文文本；
  2. 变更说明表：`Before | After | 触发的规则 | 理由`；
  3. 待确认清单：术语、技术事实、法规措辞。
- 规则号口径：变更说明填 `references/writing-rules.md` 的节.条号（如 4.1）。M/J/S 号仅用于脚本报告，不写进变更说明。dist 单文件版规则用连续数字编号。
- 中文用户：解释和变更说明用中文，交付文本用英文；不要输出逐字直译的中式英语。

## 7. 质量检查清单

### 7.1 机械检查（可脚本/grep）

- [ ] 每个程序句 ≤ 20 词；每个描述句 ≤ 25 词。
- [ ] 无分号 `;`。
- [ ] 无 em dash / en dash 连接两个独立句。
- [ ] 无 `-ing` 动词形式（技术名词除外）。
- [ ] 无 `has/have/had + 过去分词`、`is/are + -ing`。
- [ ] 无缩写：`don't / can't / won't / isn't / it's`。
- [ ] 无 `e.g. / i.e. / etc.`。
- [ ] 每个名词簇 ≤ 3 词。
- [ ] 每段 ≤ 6 句，一段一主题。
- [ ] 每条程序指令以祈使动词开头。
- [ ] 条件、警告位于动作之前。
- [ ] 无 `he / she` 作为通用指代。

### 7.2 判断检查（需人/模型逐句判断）

- [ ] 每个实词都能归类为：批准词 / 技术名词 / 技术动词 / 不可改字面量。
- [ ] 每个批准词都按批准词性和批准含义使用。
- [ ] 同一对象全文同一名称，无同义词轮换。
- [ ] 无隐喻、习语、俚语、短语动词。
- [ ] `WARNING` / `CAUTION` 级别正确，`NOTE` 不含指令。
- [ ] 冠词、主语、限定词没有被为缩短而删除。
- [ ] 技术含义未变；数字、单位、条件、失败处理未丢。
- [ ] 缩写首次出现有全称。
- [ ] 非母语读者能一次读对，不需要回读。
- [ ] 全文没有"官方认证/完全合规"的虚假声明。

### 7.3 交付判定

- 机械项**全部通过**；判断项无未解决项，或未解决项已列入待确认清单。
- 变更说明能覆盖所有实质性改动。
- 不可改内容逐一核对，无改写、无翻译、无格式化破坏。

## 8. 边界与常见误区

- **不是"baby English"**：STE 用受控方式描述复杂系统和复杂任务，仍是严谨标准。
- **不只给非母语者用**：母语者之间的沟通同样受益。
- **不消除翻译需求**：读者英语不足时仍需翻译；STE 降低的是翻译难度和成本。
- **不修正错误的技术内容**：清晰但错误的指令仍然是错误指令。STE 与工程评审并行。
- **短词不等于无歧义**：必须查词典的批准义，不能只换简单词。
- **工具不能替代标准和人**：ASD/STEMG 不认证、不背书任何检查工具；工具会漏报和误报。
- **脚本只查句法**：事实、术语、顺序需要人工判断。
- **AI 生成文本可能"看起来合规"**：必须人工复核，不能把"像 STE"当成"是 STE"。
- **不要全量铺开**：先试点、培训、建企业术语库，再推广；初期写作速度会下降。
- **注意版本**：Issue 9（2025-01）已替代 Issue 8（2021-04）；合同或样式指南若仍写 Issue 8，需确认是否迁移。
- **不要"润色"回普通英语**：为可读性换词、拆句、加修饰，都会破坏受控性。
