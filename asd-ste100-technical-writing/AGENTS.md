# AGENTS.md — ASD-STE100 英文技术写作

本仓库是英文技术文档的写作规范包。在本仓库内写、改、审**英文**技术文档时，按本文件与 `references/` 的规则执行。

中文文档请用 `ste-zh-technical-writing`。中英混合文本的分诊规则见 `docs/mixed-language.md`。

## 何时启用

- 任务涉及：维修手册、工卡、安装/拆卸/调试步骤、SOP、运行手册（runbook）、安全警告、API 运维文档。
- 用户要求：消除歧义、便于翻译、便于非母语读者一次读懂、统一术语、可机械检查。
- 行业：航空、国防、汽车、铁路、医疗器械、制药、能源、机械、IT 运维。

不启用：营销文案、法律与法规原文、文学创作、纯中文写作、个人风格文本、代码/日志本身。

## 硬约束（摘要）

**词**
- 只用词典批准词，按批准词性和批准含义使用。`start` 不用 `begin / commence / initiate`。
- 技术名词、技术动词只能用项目既有术语，不能互转，不能临时发明。
- 不用缩写形式（`don't` → `do not`）、拉丁缩写（`e.g.` → `for example`）、性别代词、隐喻、习语、短语动词。
- 不用 `-ing` 动词形式。技术名词及其修饰语（`opening`、`landing gear`）除外。
- 美式拼写。

**句**
- 程序句 ≤ 20 词，描述句 ≤ 25 词。一句一个指令。条件放在动作之前。
- 名词簇 ≤ 3 词。不省略冠词、主语、`that`。
- 三个以上同类项、连续步骤用竖排列表。一段 ≤ 6 句。

**动词**
- 只用不定式、祈使式、一般现在/过去/将来时。过去分词只作形容词。
- 禁完成时、进行时、复杂助动词堆叠。
- 程序用主动语态 + 祈使句。描述优先主动。

**安全说明**
- `WARNING` 管人身伤害或死亡。`CAUTION` 管设备、工具、财产损坏。`NOTE` 只给信息，不含指令。
- 放在受影响步骤之前。先命令或条件，再原因和后果。

**标点**
- 不用分号，不用 em/en dash 连接独立意思。
- 数字 + 单位算一个词（`10 °C` 算 1 词）。代码、命令、路径按字面量处理。

## 工作流程

1. 分类文本：程序 / 描述 / 安全说明 / 混合。确认目标版本（默认 Issue 9）。
2. 锁定不可改内容：代码、命令、路径、标识符、错误串、数字、单位、版本、UI 标签、法规原文。
3. 建术语表：技术名词与技术动词各定唯一写法。
4. 分层改写：词 → 名词簇 → 动词 → 句子 → 段落 → 安全说明 → 标点。
5. 跑检查：`python scripts/check_en.py <文件> --strict`，清掉全部【必须】级发现。
6. 语义复核：技术含义、条件、例外、单位、失败处理是否还在。
7. 交付：改写稿 + 变更说明表（`Before | After | 规则 | 理由`）+ 待确认清单。

## 输出契约

- 只改英文散文。代码、命令、路径、标识符、数字、单位、版本、日期原样保留。
- 不新增事实，不删警告、限制、例外，不改变确定性。
- 不改写法规、合同、认证原文。
- 不虚构词典批准状态。无法确认时标注"需查 Issue 9 词典"。
- 可以写"按 ASD-STE100 Issue 9 写作规则改写"。**不能**写"通过认证"或"完全合规"。
- 中文用户：解释和变更说明用中文，交付文本用英文。

## 自检

```bash
python scripts/check_en.py --strict 文档.md
python scripts/check_en.py --kind description answer.md
python scripts/check_en.py --no-lang-skip 双语文档.md   # 强制检查全部行
```

脚本只查句法。词典批准状态、词性、词义、名词簇关系、技术含义必须人工判断。

## 边界

- STE 不是"baby English"，也不修正错误的技术内容。
- 工具会漏报误报，ASD/STEMG 不认证任何检查工具。
- AI 生成的文本可能"看起来合规"，必须人工复核。
- 本 skill 不含完整词典，关键用词查官方 Issue 9 PDF。
