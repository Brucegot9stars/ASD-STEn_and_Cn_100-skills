# 受控中文写作规则（45 条 / 9 节）

标注说明：**【必须】**违反即为缺陷。**【建议】**默认执行。不执行的每处都要能说出理由。

---

## 1. 词（8 条）

### 1.1 一个概念只用一个词【必须】

同一对象、动作、状态，全文只有一个名字。

- ✗ `先删除缓存，再清除临时文件，最后移除旧日志。`
- ✓ `先清理缓存。再清理临时文件。最后清理旧日志。`
- 理由：读者会把"删除 / 清除 / 移除"读成三种不同强度的操作。

### 1.2 一个词只干一件事【必须】

`打开` 只用于文件、窗口、菜单。功能用 `启用`。程序、服务用 `启动`。电源、气源用 `接通`。

- ✗ `打开 SSH 服务，然后打开配置文件。`
- ✓ `启用 SSH 服务。打开配置文件 sshd_config。`
- 理由：中文动词的搭配范围太宽，一个动词覆盖多个对象就会丢信息。

### 1.3 不用名词化【必须】

删掉 `进行 / 加以 / 予以 / 作出 / 实施 / 开展`，直接用动词。

- ✗ `对日志进行压缩处理，并对配置加以修改。`
- ✓ `压缩日志。修改配置。`
- 理由：多两个字，多一层抽象，读者要在脑内还原真正的动作。

### 1.4 删空转词【必须】

`值得注意的是`、`综上所述`、`众所周知`、`不难看出`、`显而易见`、`总的来说`、`在一定程度上`、`在某种意义上`。

- ✗ `值得注意的是，该机制在一定程度上提升了吞吐。`
- ✓ `缓存层把突发请求排队，吞吐提高 30%。`
- 理由：这些词不提供信息，只表示"作者要转折了"。

### 1.5 不用模糊词【必须】

`尽快`、`必要时`、`酌情`、`视情况`、`适当`、`尽量`、`及时`。

- ✗ `如果服务异常，请尽快重启。`
- ✓ `如果服务在 30 s 内没有响应，重启服务。`
- 理由：模糊词把判断责任推给读者。改成可检查的条件或时限。

### 1.6 不用成语、比喻、拟人、黑话【必须】

`赋能`、`抓手`、`闭环`、`打通`、`丝滑`、`拉齐`、`对齐颗粒度`、`组合拳`。

- ✗ `打通数据链路，形成闭环。`
- ✓ `采集程序把数据写入数据库。报表程序读取数据库。`
- 理由：比喻依赖共同背景，跨团队、跨语言读者无法解码。

### 1.7 情态只留三档【必须】

`必须`（要求）、`可以`（允许）、`建议`（推荐）。能力用 `支持`，不用 `可以`。

- ✗ `管理员可以上传 2 GB 的文件。`（是允许还是能力？）
- ✓ `管理员可以上传最大 2 GB 的文件。` / `系统支持最大 2 GB 的文件。`
- 理由：`可以` 同时表示许可和能力，是中文技术文档最常见的歧义源之一。

### 1.8 术语首次出现给全称【必须】

首次出现写 `中文全称（ABBR）`。其后固定写法，同一缩写不在文内换含义。

- ✗ `配置 EGT 探头后，检查 EGT。`
- ✓ `配置排气温度（EGT）探头。检查 EGT 读数。`
- 理由：缩写对非专业读者等于生词，对专业读者也可能有多个展开。

## 2. 名词短语（4 条）

### 2.1 定语最多 3 层【必须】

超过 3 层就拆句，或先定义、再短称。

- ✗ `前部涡轮过热热电偶接线柱固定螺栓`
- ✓ `过热热电偶（以下简称 EGT 探头）装在前部涡轮上。拆下 EGT 探头接线柱的固定螺栓。`
- 理由：中文定语全部前置，层数一多，读者无法判断谁修饰谁。

### 2.2 不用"的"字链【必须】

`A 的 B 的 C 的 D` 必然读错。一个"的"以内，其余改短句。

- ✗ `服务器的主板的电源的连接器的型号`
- ✓ `服务器主板上电源连接器的型号`
- 理由：连续"的"使结构扁平化，层级消失。

### 2.3 删虚指修饰【必须】

`相关`、`有关`、`相应`、`上述`、`该`、`其`、`此`。

- ✗ `修改相关的配置文件，然后重启该服务。`
- ✓ `修改配置文件 app.conf。重启服务 nginx。`
- 理由：虚指必须靠上文推断。读者一旦断线就要回读，回读就会读错行。

### 2.4 不用空壳名词作主语【建议】

`情况`、`问题`、`方面`、`工作`、`过程`、`状态` 单独作主语时，主语其实缺失。

- ✗ `在配置过程中出现问题的情况下，需要检查日志。`
- ✓ `如果配置失败，检查日志 error.log。`
- 理由：空壳名词让句子看起来完整，实际没有说清谁做了什么。

## 3. 动词与语态（5 条）

### 3.1 操作句用祈使句，不写主语【必须】

不写 `请`、`您`、`用户需要`、`我们应该`。

- ✗ `请您先点击"保存"按钮，然后用户需要等待 5 秒。`
- ✓ `点击「保存」。等待 5 s。`
- 理由：步骤的主语永远是执行者。写出来只是增加字数。

### 3.2 用主动句【必须】

`被` 字句只在施动者未知或不重要时用，且不出现在操作步骤里。

- ✗ `温度必须被调整到 80 °C。`
- ✓ `将温度调整到 80 °C。`
- 理由：被动句隐去施动者，读者不知道自己该不该动手。

### 3.3 删"由……进行"的绕行【必须】

`由 A 对 B 进行 C` → `A 做 C`，或直接写动作。

- ✗ `由维护人员对滤芯进行更换。`
- ✓ `更换滤芯。`
- 理由：句式把动作拆成"施动者 + 介词 + 对象 + 空动词"，只增加解析成本。

### 3.4 体标记克制【必须】

步骤里不用 `已经……了`、`正在……中`、`将会`、`将要`。

- ✗ `已经完成了安装，然后系统将会开始运行。`
- ✓ `安装完成。启动系统。`
- 理由：中文靠词序和上下文表达时间。多余的时间标记会让"状态"和"动作"混淆。

### 3.5 动作写全：动词 + 对象 + 结果【必须】

不能只写动作名。`处理完成`、`检查一下`、`优化后` 都不成立。

- ✗ `处理完成后重启。`
- ✓ `删除临时文件后，重启服务。`
- 理由：没有对象的动作，读者无法判断自己做的是不是同一件事。

## 4. 句子（7 条）

### 4.1 句长上限【必须】

- 操作句 **≤ 30 字**。描述句 **≤ 40 字**。
- 安全关键文档（航空、医疗、高压、化工）用严格档：**20 字 / 30 字**。
- 统计口径：去掉空白与标点后计数。汉字每字计 1。
- 连续的字母、数字或标识符整体计 1 个词。
- 数字与单位整体计 1 个词，如 `20 N·m`、`80 °C` 各计 1 个。
- 该口径与 `scripts/check_zh.py` 的 `char_count` 一致。

- ✗ `用户首先需要登录到目标服务器，然后切换到 /opt 目录并且创建一个用于存放采集器配置文件以及运行时产生的临时数据的工作目录。`（56 字）
- ✓ `1. 登录目标服务器。2. 切换到 /opt 目录。3. 创建工作目录 /opt/collector。`
- 理由：30 / 40 取自中文技术文档句长分布的 90 分位，超过这个长度，回读率明显上升。

### 4.2 一句一个动作【必须】

两个动作必须在同一时刻完成时，才可同句，并写明 `同时`。

- ✗ `按下启动按钮并保持 3 s 后松开，观察指示灯是否变绿。`
- ✓ `按住启动按钮 3 s。松开按钮。确认指示灯为绿色。`
- 理由：一句话里三个动作，读者会漏掉中间那个。

### 4.3 条件放在动作前面【必须】

- ✗ `关闭阀门，如果压力超过 0.5 MPa。`
- ✓ `如果压力超过 0.5 MPa，关闭阀门。`
- 理由：中文习惯把长条件放后面，但操作文本里读者先看到动作就会先动手。

### 4.4 不靠连接词串步骤【必须】

`然后`、`接着`、`随后`、`之后`、`与此同时` 出现在步骤里，说明该编号了。

- ✗ `打开终端，然后输入命令，之后等待结果。`
- ✓ `1. 打开终端。2. 输入命令。3. 等待结果。`
- 理由：连接词看不出步骤边界，也无法被测试用例引用。

### 4.5 不堆并列【必须】

`并且`、`以及`、`同时` 连三个以上成分时，改列表或拆句。

- ✗ `备份数据库并且清理缓存以及重启服务。`
- ✓ `1. 备份数据库。2. 清理缓存。3. 重启服务。`
- 理由：并列项超过两项，读者无法确认顺序是否重要——而它往往重要。

### 4.6 不用反问、感叹、双重否定【必须】

- ✗ `难道不应该先备份吗？这么简单的操作千万别忘！`
- ✗ `不得不重启服务，否则无法生效。`
- ✓ `先备份数据库。重启服务后生效。`
- 理由：反问和感叹携带情绪，双重否定的解析成本是肯定句的两倍。

### 4.7 否定范围要写清【必须】

否定词紧贴被否定的成分。"全部不"否定全部，"不全"只否定部分。两者含义相反，按原意选词。

- ✗ `全部节点都不可用。`（原意：部分节点不可用）
- ✓ `部分节点不可用。`
- 理由：否定词在量词前或后，决定否定范围。读者无法从语序推回原意。

## 5. 操作步骤（5 条）

### 5.1 用编号列表【必须】

一步一号。子步骤用二级编号（`3.1`、`3.2`），不写成一段。

- ✗ `先停止服务，改配置，再启动，最后验证。`
- ✓ `1. 停止服务。2. 修改配置。3. 启动服务。4. 验证状态。`

### 5.2 以动词开头【必须】

- ✗ `服务配置文件的修改是第一步。`
- ✓ `1. 修改服务配置文件。`
- 理由：动词开头让读者一眼看到"要做什么"，也便于跨语言翻译对齐。

### 5.3 一步一个主要动作【必须】

- ✗ `3. 拆下盖板，检查密封圈，如果老化就更换，然后装回盖板。`
- ✓ 
  ```
  3. 拆下盖板。
  4. 检查密封圈。如果密封圈老化，更换密封圈。
  5. 装回盖板。
  ```

### 5.4 前置条件单列【必须】

环境、权限、工具、停机窗口写在步骤之前，不塞进括号或步骤末尾。

- ✗ `1. 执行升级脚本（需要 root 权限和 30 分钟停机）。`
- ✓ 
  ```
  前置条件：root 权限；30 min 停机窗口。
  1. 执行升级脚本。
  ```

### 5.5 结果与验证分开【必须】

- ✗ `4. 拧紧螺栓到 20 N·m 并确认扭矩合格。`
- ✓ `4. 拧紧螺栓。5. 确认扭矩为 20 N·m。`
- 理由：动作和判据混在一句，读者无法判断"做完"和"做对"是两个验收点。

## 6. 说明文字（5 条）

### 6.1 段落不超过 5 句【必须】

一段一个主题。超过 5 句就分段，或改成列表。

### 6.2 首句给结论【必须】

- ✗ `考虑到网络抖动、重试策略和超时设置之间相互影响，我们经过分析认为……`
- ✓ `重试会放大超时。每次重试都重新计时，最坏情况下总耗时是单次的 3 倍。`
- 理由：读者读技术文档是来取结论的，不是来读推导过程。

### 6.3 一个句子只承担一个逻辑关系【必须】

`由于 A，导致在 B 的情况下出现 C` 拆成三句：条件、机制、结果。

- ✗ `由于缓存未命中导致在并发较高时出现响应变慢的情况。`
- ✓ `并发高时缓存命中率下降。请求直接打到数据库。响应变慢。`

### 6.4 说明里不夹指令【必须】

要读者动手，就单列步骤。说明段落只解释。

- ✗ `该参数默认关闭，你需要手动打开它。`
- ✓ `该参数默认关闭。要启用该参数，执行第 3 步。`

### 6.5 不写背景铺垫与历史沿革【建议】

`随着业务快速发展`、`为了更好地满足需求`、`自 2019 年以来` 不进入操作文档正文。需要时放"概述"并压到一句。

## 7. 安全提示（4 条）

### 7.1 三级分类，不混用【必须】

| 级别 | 管什么 | 不管什么 |
|---|---|---|
| `警告` | 人身伤害、死亡 | 设备损坏、数据丢失 |
| `注意` | 设备、数据、财产损坏 | 人身伤害 |
| `说明` | 信息、前提、结果 | 任何操作指令 |

- ✗ `警告：误删该文件会导致服务不可用。`（应为"注意"）
- ✓ `注意：删除该文件会导致服务不可用。`

### 7.2 独立成段，放在步骤之前【必须】

不写在步骤末尾，不写成句中从句，不放进括号。

- ✗ `5. 拆下液压管（注意高温，可能烫伤）。`
- ✓ 
  ```
  警告：液压管表面温度可达 120 °C。接触会造成烫伤。戴隔热手套。
  5. 拆下液压管。
  ```

### 7.3 先命令或条件，再后果【必须】

- ✗ `排气管温度很高，如果接触可能造成烫伤，所以不要触摸。`
- ✓ `警告：不要接触排气管。排气管表面温度可达 600 °C，接触会造成严重烫伤。`
- 理由：读者在压力下只看第一句，把动作放第一位。

### 7.4 不写空提示【必须】

`请注意`、`小心`、`务必注意`、`严禁违规操作` 不提供任何可执行信息。

- ✗ `请注意安全，小心操作。`
- ✓ `戴防护眼镜。接触冷却液前戴丁腈手套。`

## 8. 数字、时间与范围（4 条）

### 8.1 不用"以上 / 以下"【必须】

`20 N·m 以上` 是否含 20，中文习惯与国标不一致，必须写清端点。

- ✗ `扭矩 20 N·m 以上为合格。`
- ✓ `扭矩不小于 20 N·m 为合格。` / `扭矩大于 20 N·m 为合格。`

### 8.2 范围写"至"【建议】

- ✗ `等待 3~5 分钟`、`压力 0.2-0.4 MPa`
- ✓ `等待 3 min 至 5 min`、`压力 0.2 MPa 至 0.4 MPa`
- 理由：`~` 和 `-` 在部分字体、部分读者眼里是减号或连字符。

### 8.3 数值与单位之间留空格【必须】

- ✗ `80℃`、`20N·m`、`5min`
- ✓ `80 °C`、`20 N·m`、`5 min`
- 例外：`%`、`°`（角度）、中文单位（`3 个月`）按项目样式统一，全文一致即可。

### 8.4 时间与变化量写清基准【必须】

- ✗ `昨天上线后延迟降低了 2 倍。`
- ✓ `2026-11-18 上线后，中位延迟从 40 ms 降到 12 ms。`
- 理由：相对时间无法复现，"降低 N 倍"在中文里没有公认含义。

## 9. 标点与标记（3 条）

### 9.1 不用分号【必须】

分号常被用来把三个动作粘成一句，应拆句或改列表。

- ✗ `停止服务；修改配置；启动服务。`
- ✓ `1. 停止服务。2. 修改配置。3. 启动服务。`

### 9.2 顿号只连同类词，括号不装指令【必须】

- ✗ `点击保存、然后等待、再刷新页面。`（顿号连了分句）
- ✓ `点击「保存」。等待 5 s。刷新页面。`
- ✗ `点击「保存」（如果已登录）。`
- ✓ `如果已登录，点击「保存」。`

### 9.3 中英混排与标记统一【建议】

- 中文与英文、数字之间留一个空格：`修改 app.conf 文件`。
- 中文用全角标点。代码、命令、路径内用半角，并用反引号：`systemctl restart nginx`。
- 界面元素全文统一用「」或加粗，不混用引号、书名号、方括号。
