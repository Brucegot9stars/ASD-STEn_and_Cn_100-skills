# AGENTS.md — 受控中文技术写作

本仓库是一个写作规范包。写、改、审中文技术文档时，按本文件与 `references/` 的规则执行。

## 何时启用

- 任务涉及：操作步骤、安装配置指南、接口文档、运维手册、SOP、工卡、说明书、安全警告。
- 用户要求：减少歧义、一句一事、一词一义、给非专业读者写说明、让 AI 说人话、统一术语。
- 用户抱怨：读不懂、啰嗦、翻译腔、同一个东西换着叫。

不启用：营销文案、法律与法规原文、文学创作、英文技术文档（英文用 `asd-ste100-technical-writing`）、个人风格文本、代码/日志本身。

中英混合文本先按段落分诊：

- `ZH` 段用本文件。
- `EN` 段用英文版 skill。
- `MIXED` 段按主导语言选一套。另一语言片段列为不可改字面量。也可拆成两段分别处理。
- `CODE` 原样保留。

一句只用一套句长上限。中英混排句按主导语言判。两个检查脚本各跑一次，默认各自跳过对方语言主导的行。合规声明分开写，中文部分不得声称"符合 ASD-STE100"。完整规范见 `docs` 目录下的 mixed-language.md。

## 硬约束（摘要）

**词**
- 一个概念全文一个词。`删除` 不混用 `移除 / 清除 / 去掉`。
- `打开` 只用于文件、窗口、菜单。功能用 `启用`，程序用 `启动`，电源用 `接通`。
- `可以` 只表允许。能力用 `支持`，要求用 `必须`，推荐用 `建议`。
- 不用 `进行 / 加以 / 予以 / 作出 / 实施 + 动词`。直接用动词。
- 删 `值得注意的是 / 综上所述 / 众所周知 / 一定程度上`。
- 模糊词（`尽快 / 必要时 / 酌情 / 适当 / 尽量`）改成可执行的条件、时限或数值。
- 不用成语、比喻、黑话。术语首次出现给全称。

**句**
- 操作句 ≤ 30 字，描述句 ≤ 40 字。安全关键文档 20 / 30 字。
- 一句一个动作。条件写在动作前面。
- 不用 `然后 / 接着 / 随后` 串步骤，改编号列表。
- `并且 / 以及` 连三个以上成分时拆句或改列表。
- 操作句动词开头，不写 `请 / 您 / 用户需要`，不用 `被` 字句。
- 不用分号。不用反问、感叹、双重否定。
- 否定范围写清。`全部不` 否定全部，`不全` 只否定部分。按原意选，别让读者猜。

**步骤**
- 编号，一步一个主要动作，动词开头。
- 前置条件单列在步骤之前，不塞括号。
- 结果与验证分开写。

**安全提示**
- `警告` 管人身伤害或死亡。`注意` 管设备、数据、财产损坏。`说明` 只管信息，不含指令。
- 独立成段，放在受影响步骤之前。
- 先命令或条件，再后果。

**数字**
- 不用"以上 / 以下"，写 `不小于 / 大于 / 不超过 / 小于`。
- 范围写 `3 min 至 5 min`，不用 `~`。
- 数值与单位之间留空格：`20 N·m`、`80 °C`。
- 时间写绝对日期。变化量写清基准，不写"降低 2 倍"。

## 工作流程

1. 分类文本：操作步骤 / 说明 / 安全提示 / 混合。
2. 锁定不可改内容：代码、命令、路径、参数、错误串、界面文字、数字、单位、法规原文。
3. 建术语表：核心对象、动作、状态各定一个首选词。
4. 分层改写：词 → 名词短语 → 动词 → 句子 → 段落 → 步骤 → 安全提示 → 标点数字。
5. 跑检查：`python scripts/check_zh.py <文件> --strict`，清掉全部【必须】级发现。
6. 语义复核：技术含义、条件、例外、单位、失败处理是否还在。
7. 交付：改写稿 + 变更说明表（`原文 | 改写 | 规则号 | 理由`）+ 待确认清单。

## 输出契约

- 只改散文。代码块、命令、路径、标识符、数字、单位、版本、日期原样保留。
- 不新增事实，不删信息，不改变确定性。
- 不改写法规、合同、认证原文。冲突时保留原文并标注。
- 不声称"符合 ASD-STE100"或"通过认证"。这是非官方写作辅助，STE 只规范英文。
- 面向中文读者解释，引用英文术语时保留原文。

## 自检

```bash
python scripts/check_zh.py --strict 文档.md
python scripts/check_zh.py --kind 描述 answer.md          # 聊天回答
python scripts/check_zh.py --max-op 20 --max-desc 30 手册.md  # 安全关键
```

脚本只做句法模式匹配。它查不出事实错误、术语是否选对、步骤顺序是否合理、指代是否唯一。这些必须人工判断。

## 边界

- 短句不等于删信息。该有的对象、条件、判据不能省。
- 不修正错误的技术内容。写得清楚但步骤错了，仍是错误步骤。
- 不消除翻译需求，降低的是翻译歧义和成本。
- AI 生成的文本最危险：通顺、术语全对、步骤是编的。技术事实必须人工核对。
